Для определения доступных сетевых служб и их версий было выполнено сканирование:

nmap -sV -O -T4 192.168.229.147

* `-sV` — определение версий запущенных сетевых служб;

## Обнаруженные уязвимости

### 1. Samba 3.0.20 — Username Map Script Command Execution

На машине была обнаружена **Samba 3.0.20-Debian**.

Для версий Samba 3.0.20–3.0.25rc3 существует уязвимость выполнения произвольных команд через параметр `username map script`.

```text
CVE: CVE-2007-2447
Exploit-DB: EDB-ID 16320
Тип: Remote Command Execution
```

В данной уязвимости специально сформированное имя пользователя может привести к выполнению команд на удалённой системе.

### 2. ProFTPD — mod_mysql Authentication Bypass

На порту `2121/tcp` была обнаружена служба:

```text
ProFTPD 1.3.1
```

Для ProFTPD с использованием модуля `mod_mysql` существует уязвимость, позволяющая обойти аутентификацию посредством SQL-инъекции.

```text
CVE: CVE-2009-0543, CVE-2009-0542
Exploit-DB: EDB-ID 8037
Тип: Remote / Authentication Bypass
```

Применимость данной уязвимости зависит от использования уязвимого модуля `mod_mysql`.

### 3. UnrealIRCd — Backdoor Command Execution

На порту `6667/tcp` Nmap обнаружил службу:

```text
UnrealIRCd
```

В Exploit-DB существует известная уязвимость для **UnrealIRCd 3.2.8.1**, позволяющая удалённо выполнять команды через встроенный backdoor.

```text
CVE: CVE-2010-2075
Exploit-DB: EDB-ID 16922
Тип: Remote Command Execution
```

В ходе сканирования служба UnrealIRCd была обнаружена, однако точный номер её версии получить не удалось: сервер ограничивал повторные подключения механизмом throttling. Поэтому данная уязвимость рассматривается как потенциально применимая к обнаруженной службе.

# Задание 2

Необходимо было провести сканирование Metasploitable четырьмя способами:

* SYN scan;
* FIN scan;
* Xmas scan;
* UDP scan.

Все сеансы сканирования были записаны с помощью **Wireshark**.

Для захвата трафика использовался сетевой интерфейс VMware, через который происходил обмен между:

```text
Windows:       192.168.229.1
Metasploitable: 192.168.229.147
```

Для отображения только нужного трафика в Wireshark использовался фильтр:

```text
ip.addr == 192.168.229.147
```

---

## 1. SYN scan

Команда:

```bash
nmap -sS -Pn -n --reason -p 1-1000 192.168.229.147
```

При SYN-сканировании Nmap отправляет на проверяемый TCP-порт пакет с установленным флагом:

```text
SYN
```

### Открытый порт

При обращении к открытому порту сервер отвечал:

```text
SYN, ACK
```

После получения ответа Nmap отправлял `RST`, не завершая полноценное TCP-соединение.

Схема:

```text
Nmap                         Metasploitable

SYN        -------------------->
           <-------------------- SYN, ACK
RST        -------------------->
```

Таким образом, полноценное TCP three-way handshake не выполняется.

### Закрытый порт

Закрытые TCP-порты отвечали:

```text
RST, ACK
```

Nmap при этом определял их состояние как:

```text
closed
```

---

## 2. FIN scan

Команда:

```bash
nmap -sF -Pn -n --reason -p 1-1000 192.168.229.147
```

При FIN-сканировании вместо попытки установить TCP-соединение Nmap отправляет пакет с установленным флагом:

```text
FIN
```

В Wireshark были видны многочисленные пакеты:

```text
[FIN]
```

### Открытый порт

Открытые порты Metasploitable на FIN-пакет ответа не отправляли.

Nmap показывал:

```text
open|filtered
Reason: no-response
```

Это связано с тем, что отсутствие ответа не позволяет Nmap однозначно определить, открыт порт или пакет был отброшен сетевым фильтром.

### Закрытый порт

Закрытые порты отвечали:

```text
RST, ACK
```

Схема:

```text
Открытый порт:

FIN        -------------------->
           <-------------------- нет ответа


Закрытый порт:

FIN        -------------------->
           <-------------------- RST, ACK
```

---

## 3. Xmas scan

Команда:

```bash
nmap -sX -Pn -n --reason -p 1-1000 192.168.229.147
```

Xmas scan отличается тем, что Nmap устанавливает одновременно несколько TCP-флагов:

```text
FIN
PSH
URG
```

В Wireshark исходящие пакеты отображались как:

```text
[FIN, PSH, URG]
```

Название Xmas связано с тем, что одновременно установлено сразу несколько флагов TCP-пакета.

### Открытый порт

Открытые TCP-порты не отправляли ответ.

Nmap определял их как:

```text
open|filtered
Reason: no-response
```

### Закрытый порт

Закрытые порты отвечали:

```text
RST, ACK
```

Таким образом, реакция сервера на Xmas scan оказалась практически такой же, как при FIN scan. Отличается прежде всего набор TCP-флагов в отправляемом пакете.

---

## 4. UDP scan

Команда:

```bash
nmap -sU -Pn -n --reason --top-ports 100 192.168.229.147
```

UDP работает без установки TCP-соединения, поэтому флаги `SYN`, `FIN`, `RST` и другие TCP-флаги здесь отсутствуют.

Nmap отправлял UDP-пакеты на проверяемые порты.

В результате были, например, обнаружены:

```text
53/udp    open          domain
111/udp   open          rpcbind
137/udp   open          netbios-ns
2049/udp  open          nfs
```

Для этих портов Nmap получил UDP-ответ:

```text
udp-response
```

Также были обнаружены закрытые UDP-порты, например:

```text
17/udp
1646/udp
49191/udp
```

При обращении к закрытому UDP-порту Metasploitable отвечала ICMP-сообщением:

```text
Destination Unreachable
Port Unreachable
```

Nmap отображал причину как:

```text
port-unreach
```

Часть UDP-портов вообще не отправляла ответа. В таком случае Nmap определял их как:

```text
open|filtered
Reason: no-response
```

# Сравнение режимов сканирования

| Режим | Отправляемый трафик | Ответ открытого порта           | Ответ закрытого порта   |
| ----- | ------------------- | ------------------------------- | ----------------------- |
| SYN   | TCP `SYN`           | `SYN, ACK`                      | `RST, ACK`              |
| FIN   | TCP `FIN`           | Нет ответа                      | `RST, ACK`              |
| Xmas  | TCP `FIN, PSH, URG` | Нет ответа                      | `RST, ACK`              |
| UDP   | UDP datagram        | UDP-ответ или отсутствие ответа | ICMP `Port Unreachable` |

## Чем отличаются режимы с точки зрения сетевого трафика?

**SYN scan** имитирует начало обычного TCP-соединения. Nmap отправляет `SYN`, но при получении `SYN, ACK` не завершает соединение и сбрасывает его с помощью `RST`.

**FIN scan** отправляет TCP-пакет только с флагом `FIN`, несмотря на то что TCP-соединение до этого не устанавливалось.

**Xmas scan** отправляет необычный TCP-пакет сразу с тремя установленными флагами — `FIN`, `PSH` и `URG`.

**UDP scan** принципиально отличается от остальных вариантов, поскольку использует UDP вместо TCP и поэтому не содержит TCP-флагов.

## Как отвечает сервер?

При **SYN scan** открытый TCP-порт отвечает `SYN, ACK`, а закрытый — `RST, ACK`.

При **FIN scan** открытый порт обычно не отвечает, а закрытый возвращает `RST, ACK`.

При **Xmas scan** поведение аналогично FIN: открытые порты не отвечают, а закрытые возвращают `RST, ACK`.

При **UDP scan** открытая UDP-служба может вернуть обычный UDP-ответ. Закрытый UDP-порт возвращает ICMP-сообщение `Destination Unreachable: Port Unreachable`. Если ответа нет вообще, Nmap не может однозначно отличить открытый порт от фильтруемого и показывает состояние `open|filtered`.
